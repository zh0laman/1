# Техническое задание: API для Дашборда управления (Dashboard Summary)

## 1. Общее описание
Необходимо реализовать единый эндпоинт для получения агрегированных данных главного дашборда. Цель — предоставить фронтенду все необходимые данные для отрисовки виджетов (счетчики, графики, прогресс) за один запрос, минимизируя нагрузку на сеть и клиентскую часть.

**Эндпоинт:** `GET /api/v1/dashboard/summary`

---

## 2. Структура ответа (JSON)


## 3. Описание блоков и логика данных

### 3.1. Блок "Верхние карточки" (объект `summary`)
Этот блок содержит 4 компактных виджета со статистикой.
*   **active_tasks**: Задачи в статусе "В работе".
    *   `count`: Текущее кол-во задач у пользователя.
    *   `trend_percentage`: Изменение в % по сравнению с аналогичным периодом вчера.
    *   `sparkline`: Массив последних 7 значений (кол-во активных задач на конец каждого дня) для отрисовки волнообразного графика.
*   **meetings_today**: Кол-во встреч из календаря, запланированных на текущую дату.
*   **documents**: Кол-во новых или измененных документов в системе за текущую неделю.
*   **weekly_points**: Набранные баллы (геймификация) за текущую неделю.
    *   `today_points`: Кол-во баллов, полученных пользователем именно сегодня.

### 3.2. Блок "Динамика: Эффективность" (объект `efficiency_dynamics`)
Линейный график (Line Chart) эффективности работы за текущую неделю.
*   `average_load`: Среднее арифметическое нагрузки за неделю.
*   `labels`: Список дней недели (массив строк).
*   `datasets`: Два массива данных:
    1.  `Текущая`: Реальные показатели эффективности пользователя по дням.
    2.  `Ориентир`: План или средний показатель по компании для сравнения.

### 3.3. Блок "Структура: Статусы задач" (объект `task_structure`)
Горизонтальный столбчатый график распределения задач пользователя по статусам.
*   `total_count`: Сумма всех задач пользователя во всех колонках.
*   `stats`: Массив объектов. Каждый объект — название статуса и количество задач в нем. Обязательные статусы: *Ожидает, В работе, Проверка, Готово*.

### 3.4. Блок "Прогресс: Выполнение" (объект `completion_progress`)
Круговой индикатор (Donut Chart) выполнения общего объема работ.
*   `completed_count`: Кол-во задач в финальном статусе ("Готово").
*   `total_count`: Общее кол-во задач, за которые ответственен пользователь.
*   `percentage`: Процент выполнения (целое число от 0 до 100).

---

## 4. Технические требования и расчеты
1.  **Контекст:** Данные должны возвращаться только для авторизованного пользователя.
2.  **Период расчета:** По умолчанию расчет идет за текущую календарную неделю (с понедельника 00:00 по воскресенье 23:59).
3.  **Логика трендов:** `trend_percentage` рассчитывается как `((текущее_значение - предыдущее_значение) / предыдущее_значение) * 100`. Если предыдущее значение равно 0, а текущее > 0, тренд равен 100%.
4.  **Типы данных:** Числа должны возвращаться как `number`, строки как `string`.
5.  **Отсутствие данных:** Если в каком-то блоке нет данных, необходимо возвращать `0` или пустой массив `[]`, но не `null`.
